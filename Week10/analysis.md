표의 최솟값은 이 입력·구현·환경의 관측 결과다. 병합은 입력 순서와 무관하게 분할·병합하지만 슬라이싱과 리스트 생성 비용을 부담한다. Quick은 중간 위치 피벗이 정렬·역순에서 극단 피벗을 피할 수 있으나 중간 위치가 값의 중앙값을 보장하지는 않는다. 중복 키는 <= 분할에서 한쪽으로 몰리므로 현재 2-way Quick의 비용이 커진다. Radix는 값끼리 비교하지 않고 자릿수마다 버킷에 배치하므로, 키 범위가 작고 자릿수가 적은 조건에서 이점을 얻을 수 있다. 실제 승자는 위 표에 맞춰 판단하며 특정 알고리즘이 모든 입력에서 빠르다고 일반화하지 않는다.

## Q4. Quick 중복 개선: 3-way partition 확장 설계

구간을 피벗보다 작은 부분, 같은 부분, 큰 부분으로 나눈다. lt·i·gt 포인터를 두고 a[i]<pivot이면 lt와 교환한 뒤 lt와 i를 늘리고, a[i]>pivot이면 gt와 교환한 뒤 gt만 줄여 새 a[i]를 다시 검사하며, 같으면 i만 늘린다. 같은 구간은 이미 값 기준으로 확정되어 재분할하지 않고 양옆 구간만 정렬한다. 전부 같은 입력은 한 번의 선형 분류로 끝나므로 현재 2-way의 Θ(n²) 문제를 완화한다. 모든 가능한 입력의 최악 O(n²)을 없애거나 안정성을 보장하는 방법은 아니며, 작은 구간 우선 처리를 유지하면 보류 스택도 제어할 수 있다. 이 항목은 선택 확장 설계이고 이번 CSV는 원래 2-way Quick의 결과다.

## Q6. 속도·메모리·안정성·키 제한을 포함한 선택

| 특성 | Merge | 현재 Quick | LSD Radix |
|---|---|---|---|
| 원본과 반환 | 원본 유지, 새 리스트 | 원본 수정, 같은 리스트 | 원본 유지, 새 리스트 |
| 안정성 | 안정: 동점이면 왼쪽 먼저 | 불안정: 피벗 이동·교환 | 안정: 버킷 삽입 순서 유지 |
| 시간 | 최선·평균·최악 Θ(n log n) | 최선·평균 Θ(n log n), 최악 Θ(n²) | O(d(n+b)) |
| 피크 보조공간 | O(n), 호출 깊이 O(log n) | O(log n) 명시적 스택 상한 | O(n+b) |
| 키 | 비교 가능한 키 | 비교 가능한 키 | 정확한 int형의 0 이상 키; bool·음수·실수 거부 |

Quick의 평균 Θ(n log n)은 무작위 순열 등 균형 분할이 기대되는 입력 가정에서의 결과이며 결정적인 중간 위치 피벗이 모든 입력에서 그 시간을 보장한다는 뜻은 아니다. 안정성과 예측 가능한 최악 시간을 원하고 선형 추가 메모리가 가능하면 병합을 고려한다. 현재 Quick은 원본 변경이 가능하고 안정성이 불필요할 때 고려할 수 있으나 중복과 피벗 편향을 점검해야 한다. 제한된 자릿수의 비음수 정수 키에는 기수를 고려하며 일반 문자열·음수·실수 비교 정렬의 대체물로 취급하지 않는다. 입력 보존이 필요하면 Quick에 주는 사본의 비용도 실제 시스템에서는 부담하지만, 이번 실험의 공통 준비 복사는 타이머 밖에서 제외했다. 위 메모리 수치는 구조에 대한 점근 분석이며 바이트 단위 메모리를 실측한 결과가 아니다.

## 수기 추적 답안

### 병합

분할: [5,1,4,2,8] → [5,1] / [4,2,8] → [5]/[1], [4]/[2,8] → [2]/[8]. 병합은 다음 순서로 진행한다.

| 왼쪽 정렬 결과 | 오른쪽 정렬 결과 | 병합 결과 |
|---|---|---|
| `[5]` | `[1]` | `[1, 5]` |
| `[2]` | `[8]` | `[2, 8]` |
| `[4]` | `[2, 8]` | `[2, 4, 8]` |
| `[1, 5]` | `[2, 4, 8]` | `[1, 2, 4, 5, 8]` |


### Quick 첫 분할

중간 인덱스 2의 값 4를 끝으로 옮겨 pivot=4로 사용한다. 중간 인덱스는 통계적 중앙값을 찾는 연산이 아니다.

| 단계 | 배열 |
|---|---|
| 초기 | `[5, 1, 4, 2, 8]` |
| 중간 원소 4를 끝으로 이동 | `[5, 1, 8, 2, 4]` |
| j=0, i=0 | `[5, 1, 8, 2, 4]` |
| j=1, i=1 | `[1, 5, 8, 2, 4]` |
| j=2, i=1 | `[1, 5, 8, 2, 4]` |
| j=3, i=2 | `[1, 2, 8, 5, 4]` |
| 피벗 최종 위치 i=2 | `[1, 2, 4, 5, 8]` |

첫 분할 후 피벗 인덱스는 2이고 왼쪽 [1,2], 오른쪽 [5,8]로 나뉜다. 이 예제의 첫 분할 결과가 우연히 전체 정렬 상태이지만, 일반적으로는 양쪽 구간을 계속 정렬해야 한다.

### Radix

| 자리 | 패스 결과 |
|---|---|
| exp=1 | `[170, 90, 802, 2, 24, 45, 75, 66]` |
| exp=10 | `[802, 2, 24, 45, 66, 170, 75, 90]` |

각 자리의 버킷에서 원래 상대 순서를 유지해야 앞서 정렬한 낮은 자릿수의 순서가 보존된다.

## 복잡도 질문 답안

병합은 두 절반의 재귀 정렬과 전체 원소 수에 비례하는 병합으로 T(n)=2T(n/2)+Θ(n)이다. 약 log₂n개 레벨에서 총 Θ(n) 작업을 하므로 Θ(n log n)이다. 같은 키의 Quick은 <= 비교 때문에 매번 피벗이 끝으로 가며 n−1, n−2, …, 1개의 비교가 누적되어 Θ(n²)이다. Radix는 두 키의 대소 비교만으로 순서를 결정하는 비교 정렬 모델이 아니라 자릿수에 직접 접근하므로 비교 정렬의 Ω(n log n) 하한을 위반하지 않는다. 모두 0인 키는 기수 패스가 0회라도 초기 복사·키 검증이 Θ(n)이다.
